# Sec Searcher

Локальная проверка исходного кода на потенциальные уязвимости: **ZIP → FastAPI → Deep Agents + Graphify → llama.cpp → JSON-отчёт**.

Загрузите архив проекта в веб-интерфейсе. Сервис покажет ход анализа, покрытие файлов и находки с критичностью, CWE, цитатой из кода и рекомендацией. Отчёт можно скачать, проверку — остановить. Исходный код не исполняется.

## Быстрый запуск

Проверенное локальное окружение: Python 3.14, macOS / Apple Silicon. Нужны [uv](https://docs.astral.sh/uv/getting-started/installation/) установленный `llama-server` и GGUF-модель в `models/`. Используем **Qwen3.6-35B-A3B UD-Q3_K_M от Unsloth**; источник и контрольные суммы — в [описании моделей](models/README.md).

```sh
uv sync --locked
llama-server -m models/Qwen3.6-35B-A3B-UD-Q3_K_M.gguf \
  --alias sec-qwen36-unsloth --host 127.0.0.1 --port 8080 \
  -c 32768 -np 1 --jinja --reasoning off \
  --chat-template-kwargs '{"enable_thinking":false}' --cache-ram 0
```

В другом терминале из корня проекта:

```sh
uv run sec-searcher --agent-steps 100
```

Откройте **http://127.0.0.1:8765**, загрузите ZIP и запустите проверку. Без доступной модели интерфейс работает, но анализ недоступен.

## Установщик

Из скачанного проекта — полная сборка и запуск:

```sh
bash install.sh
```

Скрипт проверит Docker / Compose, соберёт приложение через uv, скачает стандартную GGUF-модель (~16.6 ГБ), проверит SHA256 и запустит сервис. На Apple Silicon автоматически выбирается нативный llama.cpp с Metal, на остальных платформах — CPU-контейнер. Нужен уже установленный и запущенный Docker. Повторный запуск использует существующие исходники и веса; `.env` не перезаписывается.

```sh
bash install.sh --backend metal          # macOS Apple Silicon: Metal + FastAPI в Docker
bash install.sh --backend cpu            # CPU llama.cpp в Docker
bash install.sh --build-only             # только сборка, без модели и запуска
bash install.sh --no-download            # использовать существующую стандартную модель
bash install.sh --model-file custom.gguf --no-download
```

Другой файл модели заранее поместите в `models/`. Его совместимость и контрольную сумму проверяйте самостоятельно; автоматическая проверка SHA256 настроена для стандартной Unsloth Qwen.

Установка из GitHub в чистый каталог:

```sh
curl -fsSL https://raw.githubusercontent.com/a-tsitanov/sec-searcher/main/install.sh | \
  bash -s -- --repo https://github.com/a-tsitanov/sec-searcher.git --ref main
```

Для закреплённой версии замените `main` в URL скрипта и `--ref main` одним тегом или SHA коммита. Если репозиторий закрытый, сначала клонируйте его по SSH и запустите `bash install.sh` локально. По умолчанию проект размещается в `~/sec-searcher`; другой каталог задаётся через `--dir`. Существующий checkout повторно используется без обновления и сброса изменений; `--ref` применяется при первой установке.

Для Metal нужны macOS Apple Silicon и Docker Desktop. Если `llama-server` отсутствует, установщик выполнит `brew install llama.cpp`; Homebrew должен быть установлен заранее. Проверяется наличие Metal-устройства, модель запускается с `--n-gpu-layers 999`. Перед переключением остановите прежние сервисы на портах 8765 и 8080; установщик не завершает чужие процессы. Команды после установки:

```sh
cd ~/sec-searcher  # либо каталог, из которого запускали install.sh
# Metal:
docker compose -f compose.metal.yaml --env-file .env.install logs -f app
bash scripts/metal.sh status
tail -f .runtime/metal.log
# Остановить оба компонента:
docker compose -f compose.metal.yaml --env-file .env.install down
bash scripts/metal.sh stop
# Для CPU используйте compose.yaml; отдельной остановки нативной модели нет.
```

В режиме Metal установщик ждёт `/health` модели и затем проверяет доступ к ней из приложения. В CPU-режиме ждёт только готовности приложения; загрузка модели может продолжаться. Нативная модель работает в фоне под управлением `launchd` и не запускается автоматически после перезагрузки Mac — повторите установщик или `bash scripts/metal.sh start`. Полный список параметров: `bash install.sh --help`.

## Docker

```sh
docker compose build
docker compose up -d
```

Файл модели `.gguf` должен уже лежать в `models/`. Для другого имени скопируйте `.env.example` в `.env` и измените `MODEL_FILE`. Интерфейс: **http://127.0.0.1:8765**. Если локальный сервис уже занимает этот порт, сначала остановите его.

Compose запускает сервис и отдельный **CPU**-контейнер llama.cpp. Веса подключаются только для чтения и не попадают в образ. Для Apple Silicon используйте `bash install.sh --backend metal`. Сборка требует доступа к реестрам образов и Python-пакетов; модели автоматически не скачиваются.

```sh
docker compose logs -f app llama
docker compose down
```

Настройка сети, отдельная сборка, ограничения и проверка контейнера — в [docs/DOCKER.md](docs/DOCKER.md).

## Как проходит анализ

1. ZIP проверяется и распаковывается во временный каталог. Сервис создаёт неизменяемый снимок подходящих текстовых файлов.
2. Graphify строит AST-граф связей без LLM. Агент может искать символы, соседей и пути в графе.
3. Управляемый обход передаёт очередные непрочитанные фрагменты; модель дополнительно выбирает поиск и чтение связанных файлов.
4. Находки сохраняются по мере анализа. Финальный `submit_report` формирует сводку и ограничения; цитаты проверяются по прочитанному исходному коду.

Чтение всех файлов не гарантирует обнаружение всех уязвимостей. Валидная цитата подтверждает связь с кодом, а не эксплуатацию. `partial` означает незавершённый анализ или ошибки; проверяйте также пропуски и ограничения отчёта. Результаты требуют проверки человеком.

## Настройки

| Параметр `sec-searcher` | По умолчанию | Назначение |
| --- | --- | --- |
| `--port` | `8765` | Порт интерфейса |
| `--host` | `127.0.0.1` | `0.0.0.0` для контейнера |
| `--llama-host` / `--llama-port` | `127.0.0.1` / `8080` | Адрес доверенного llama-server |
| `--agent-steps` | `30` | Число шагов, 1–500; для проектов в примерах 100 |
| `--max-output-tokens` | `8192` | Лимит ответа модели, 256–16384 |
| `--agent-seconds` | `1800` | Время работы агента, 60–7200 секунд |
| `--no-graphify` | выключен | Отключить граф |
| `--no-managed-traversal` | выключен | Передать обход полностью модели |

В интерфейсе доступны агентный и последовательный режимы. Лимиты шагов, времени и ответа в таблице относятся к агенту; последовательный режим читает фрагменты по порядку с ответом до 4096 токенов.

## Данные и ограничения

FastAPI запускается через Uvicorn в одном worker: состояние хранится в памяти процесса. Сервис рассчитан на одного локального пользователя и одну активную проверку. Последний отчёт хранится в памяти: **скачайте JSON до перезапуска**. Следующая загрузка заменяет временный проект. В контейнере временные файлы находятся в `/tmp`.

Лимиты: ZIP до 25 МиБ, распаковка до 32 МиБ / 5000 записей; снимок до 500 файлов / 8 МиБ, один файл до 192 КиБ. Зависимости, бинарные файлы, `.env*` и lock-файлы исключаются. Пропуски перечислены в отчёте. Архив с опасными путями или ссылками отклоняется.

Встроенные shell-инструменты и произвольный доступ агента к файловой системе заблокированы. HTTP-прокси окружения отключены для запросов модели. Host, Origin и CSRF проверяются, но пользовательской аутентификации нет: интерфейс предназначен для localhost.

## Разработка

```sh
uv run python -m unittest discover -s tests -v
uv pip check
```

Зависимости и CLI описаны в `pyproject.toml`, точные версии закреплены в `uv.lock`. Добавляйте зависимости через `uv add`, устанавливайте через `uv sync --locked`. Python 3.14 задан в `.python-version`. Пакет устанавливается из `src/`; подмена `PYTHONPATH` не нужна.

```text
src/sec_searcher/
  api.py                       FastAPI: маршруты, валидация и HTTP-защита
  service.py                   состояние проверки и временные проекты
  cli.py                       команда sec-searcher, запуск Uvicorn
  archives.py, scanner.py      распаковка, llama.cpp и анализ файлов
  agent_scan.py, local_chat.py Deep Agents и адаптер инструментов
  project_graph.py, graphify_worker.py  изолированная индексация
  web/                         статические файлы интерфейса
scripts/                       утилиты проверки моделей и бенчмарков
tests/                         автоматические тесты и фикстуры
docs/                          API, Docker, результаты экспериментов
pyproject.toml, uv.lock         пакет и воспроизводимое окружение
models/, benchmarks/, reports/ локальные данные (не входят в образ)
```
