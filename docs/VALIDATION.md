## Функциональная проверка

**22 автоматических теста прошли.** Они проверяют ZIP и HTTP-защиту, область доступа файловых инструментов, лимиты, отмену, неполный охват, выдуманные ссылки, сохранение нерешённых находок и цикл настоящего Deep Agents с тестовым HTTP API. ## Проверка настоящей модели

Запущен `evaluate.py`: оба учебных проекта загружены как ZIP через HTTP, исходники не исполнялись. Полный машинный отчёт: `reports/live-evaluation.json`.

| Пример | Ожидание | Результат |

Последний прогон занял примерно 16 и 15 секунд соответственно, 4 и 7 основных шагов агента. `status=done` в API означает завершение процедуры с отчётом и полным охватом чтения; это не признак правильности выводов. Сам `evaluate.py` завершился с кодом 1, поскольку оба строгих критерия не выполнены.

Вывод: загрузка, чтение нескольких файлов, поиск и формирование отчёта работают. Качество этой модели/конфигурации недостаточно для автоматического принятия решений о безопасности. Эти два примера используются при разработке и не являются независимым бенчмарком. Сравнение с VulnLLM-R на тех же примерах приведено ниже; следующая оценка должна включать другие проекты.

## Найденные несовместимости

- Большие ограничения `maxLength` в схемах инструментов приводили к ошибке генератора грамматики llama.cpp. Они остаются в серверной валидации, но исключены из схемы, отправляемой модели.
- Нативные `tool_calls` у этой связки возвращались обычным текстом, в том числе с актуальным официальным шаблоном Qwen. Поэтому рабочий режим использует JSON-адаптер. `evaluate.py --probe` и `--template` оставлены для диагностики нативного протокола; успех адаптера не означает успех нативного режима.
- При требовании копировать цитаты модель допускала несовпадения и затем убирала находку. Теперь модель выбирает только прочитанный диапазон строк, а цитату формирует сервис. Если модель отказывается от ранее отклонённой находки без исправленного отчёта, проверка помечается как незавершённая.
- Проверка интерфейса в управляемом браузере не выполнена: инструмент не смог инициализироваться (`Cannot redefine property: process`). Синтаксис JavaScript проверен; HTTP-сценарий проверен отдельно.

## Сравнение с VulnLLM-R-7B

Скачана VulnLLM-R-7B Q5_K_M (5 444 832 160 байт), SHA256 сверена с метаданными Hugging Face. Источник — GGUF сообщества mradermacher, фиксированная ревизия и хеши кода/фикстур сохранены в `models/vulnllm-run-manifest.json`.

Повторён тот же полный сценарий ZIP → HTTP → Deep Agents → llama.cpp. Код агента, JSON-адаптер, фикстуры, критерии и лимиты не менялись (хеши сверены). Контекст 16384, ответ до 2048 токенов, temperature=0, один слот. Для VulnLLM используется встроенный шаблон чата, для Qwen использовался официальный Qwen-шаблон; нативные tool calls здесь не проверялись.

| Критерий | Qwen2.5-Coder-7B | VulnLLM-R-7B |
| --- | --- | --- |
| Найдена SQL-инъекция CWE-89 | Да | Да |
| В доказательствах есть HTTP-ввод и SQL из разных файлов | Нет | Нет |
| Безопасный пример без ложных находок | Нет | Да |
| Полное чтение обоих файлов в обоих примерах | Да | Да |
| Строго пройдено примеров | 0/2 | 1/2 |
| Время: уязвимый / безопасный | 16,08 / 15,07 с | 18,09 / 10,05 с |
| Шаги: уязвимый / безопасный | 4 / 7 | 5 / 5 |

VulnLLM в обоих случаях вызвала список файлов, поиск `__import__`, чтение `repository.py`, чтение `routes.py`, затем отправку отчёта. Ошибок инструментов и пропусков чтения не было. Для уязвимого варианта указала конкатенацию SQL в строках 4–7 `repository.py` и корректно предложила параметризованные запросы. Для безопасного варианта распознала параметры и не сформировала находок; отдельно отметила ограниченность контекста авторизации.

Итог: в этом прогоне исчезло ложное срабатывание Qwen, но требование доказать межфайловую цепочку пока не выполнено. `evaluate.py` завершился с кодом 1. Два учебных примера и один прогон на модель не позволяют судить об общей точности или устойчивости; результат относится к указанной связке модели и JSON-адаптера.

Отчёты: [Qwen](../reports/qwen-coder-evaluation.json), [VulnLLM](../reports/vulnllm-evaluation.json). GGUF и отчёты исключены из Git. После этого прогона сервер был переключён на Qwen3.6 (см. ниже).


## Qwen3.6-35B-A3B UD-Q3_K_M от Unsloth

6 сентября 2026 скачана и проверена по SHA256 сборка Unsloth. Модель запущена в llama.cpp b9290 на том же Mac, контекст 16384, один слот, thinking отключён, дополнительный RAM-кэш промптов отключён. Схемы, промпт, код агента, фикстуры, temperature=0, лимит ответа 2048 и критерии тестов сохранены; хеши кода и фикстур повторно сверены. Это сравнение в прежнем JSON-адаптере, а не проверка максимальных возможностей модели с настройками, рекомендуемыми её разработчиками.

| Модель | Уязвимый ZIP: CWE-89 и доказательства из двух файлов | Безопасный ZIP: без находок | Строго пройдено | Время, уязвимый / безопасный |
| --- | --- | --- | --- | --- |

| Qwen3.6-35B-A3B UD-Q3_K_M Unsloth | PASS | PASS | **2/2** | **16,16 / 10,15 с** |

В обоих случаях Qwen3.6 сделала четыре шага: список файлов → чтение repository.py → чтение routes.py → submit_report. Полностью прочитаны все 17 строк двух файлов, ошибок и пропусков нет. В уязвимом случае описана цепочка HTTP-параметр → find_users → конкатенация SQL, приложены строки 5–7 repository.py и 7–10 routes.py. Рекомендация использовать параметры корректна. В безопасном случае модель распознала sqlite-параметр `?` и не выдала находок.

Прогон `evaluate.py` завершился с кодом 0. Модель назвала SQL-инъекцию critical, но этот уровень критичности тестом не подтверждён: сценарий проверяет обнаружение и цитаты, не реальную эксплуатацию и не CVSS. Два учебных проекта и один прогон не являются общей оценкой точности; для следующего этапа нужны независимые примеры других CWE и безопасные контрпримеры.

Отдельный `evaluate.py --probe` успешно получил нативный `tool_calls` с `list_project_files` и аргументами `{}` (`finish_reason=tool_calls`, 15 выходных токенов). Это только один простой вызов, полноценный прогон Deep Agents с нативным протоколом не выполнялся. Рабочий сервис продолжает использовать прежний JSON-адаптер.

В логах генерация около 44 токенов/с на одном из запросов. Замеры системного swap: 19088,19 МиБ во время запуска и 19533,69 МиБ после тестов. Это память всей системы; замера до запуска нет, приписывать её целиком модели нельзя. RSS процесса без учёта всех Metal-буферов не даёт полного расхода памяти модели. Запуск и оба теста завершились, но запас памяти при больших проектах отдельно не проверен.

Артефакты: [полный отчёт](../reports/qwen36-unsloth-evaluation.json), [сводка нативного вызова](../reports/qwen36-native-probe-summary.json), [лог llama-server](../reports/qwen36-llama-server.log), [манифест](../models/qwen36-unsloth-run-manifest.json). ## Graphify и управляемый обход

Добавлен настоящий Graphify (`graphifyy==0.9.55`), закреплённый вместе с зависимостями. AST-разбор запускается отдельным процессом над копией неизменяемого снимка. Семантическое LLM-обогащение и установка Graphify skills не используются. Для Deep Agents доступны три ограниченных инструмента: graph_symbols, graph_neighbors, graph_path. Веб-сервис по умолчанию включает граф и очередь новых фрагментов; флаги --no-graphify и --no-managed-traversal позволяют сравнить режимы.

Всего прошли **37 автоматических тестов**: основной набор из 34, затем повтор уточнённого теста графа и три дополнительные проверки (продолжение при отказе графа, неполный охват при малом бюджете, инструменты графа через JSON-адаптер). Проверены реальные межфайловые вызовы Graphify, неисполнение загруженного Python-кода с побочным эффектом, запрет выхода путей за снимок, таймаут/отмена индексации, отдельный учёт индексации и чтения, отклонение раннего отчёта и непрерывная пагинация обязательной очереди. Тесты используют scripted HTTP-модель, а не оценивают точность Qwen. node --check и pip check также прошли.

Сохранены локальные индексы: reports/nodegoat-graphify-index.json и reports/benchmark-python-graphify-index.json. NodeGoat: 204 узла / 247 связей / 24 файла с узлами; один повторяющийся идентификатор исключён как неоднозначный. BenchmarkPython: 57 узлов / 64 связи / 15 файлов с узлами. В последнем графе есть внешние init(), но отсутствуют вложенные обработчики тестов. Шаблоны и ресурсы без узлов остаются в очереди чтения. Граф не является полным графом вызовов или анализом потоков данных.

Параметры и SHA256 реальных прогонов: reports/graphify-run-manifest.json. Измерения с графом и контрольным обходом без графа приведены в [BENCHMARKS.md](BENCHMARKS.md).


Реальное сравнение Graphify завершено: все четыре учитываемых прогона partial, Qwen ни разу не вызвала инструменты графа. NodeGoat с графом — 30/35 файлов, одна находка; контрольный повтор после перезапуска llama.cpp — 23/35, одна подтверждённая CWE-95, остановка из-за обрезанного ответа на 19-м шаге (519,25 с). Прошли 39 тестов после изменения лимитов, затем все 26 агентных тестов после исправления финализации (всего 41 тест в актуальном наборе; остальные неизменённые проверки прошли в первом запуске).
