# Sec Searcher

Небольшой локальный сервис проверки исходников на потенциальные уязвимости через **Deep Agents + Graphify + llama.cpp**. Загружаете ZIP со всей структурой проекта, выбираете модель и получаете отчёт: критичность, путь к файлу, строка, CWE, объяснение и рекомендация. Интерфейс на русском, есть прогресс, остановка, фильтр критичности и экспорт JSON.

## Запуск

Нужны Python 3.11+ и `llama-server` с GGUF-моделью, поддерживающей вызов инструментов. Проверено окружение Python 3.14 / macOS / Apple Silicon. Установите зависимости:

```sh
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements.lock.txt
```

Прямые зависимости закреплены в `requirements.txt`, полное проверенное окружение — в `requirements.lock.txt`.

В первом терминале запустите модель (замените путь на свой):

```sh
llama-server -m models/Qwen3.6-35B-A3B-UD-Q3_K_M.gguf --alias sec-qwen36-unsloth --host 127.0.0.1 --port 8080 -c 32768 -np 1 --jinja --reasoning off --cache-ram 0
```

Во втором, из папки проекта:

```sh
.venv/bin/python server.py
```

Откройте **http://127.0.0.1:8765**, выберите ZIP и нажмите «Проверить проект». Модели загружаются из `/v1/models`. Если llama-server работает на другом порту:

```sh
.venv/bin/python server.py --port 8765 --llama-port 8081
```

Подключение использует локальный `/v1/chat/completions`. Агентный режим использует строгий JSON-выбор инструмента через адаптер `local_chat.py`; Deep Agents получает стандартные tool calls. Последовательный режим использует JSON Schema для находок. Нативный протокол доступен в `scan_agent(..., protocol="native")` для тестирования других моделей, но на данной связке Qwen/llama.cpp он не прошёл проверку. См. [документацию llama-server](https://github.com/ggml-org/llama.cpp/blob/master/docs/function-calling.md).

Текущая проверенная модель — **Qwen3.6-35B-A3B UD-Q3_K_M от Unsloth**. Источник, SHA256 и команды других моделей — в [models/README.md](../models/README.md). Результаты сравнения с Qwen2.5-Coder и VulnLLM-R — в [VALIDATION.md](VALIDATION.md). Старые веса Qwen2.5-Coder удалены для освобождения диска, отчёты сохранены. Сервис не скачивает модели автоматически.

## Режимы

**Deep Agents** (по умолчанию): настоящий `create_deep_agent` из пакета `deepagents`. Модель выбирает поиск и чтение связанных файлов через `list_project_files`, `search_project`, `read_project_file`. Для каждой обоснованной находки вызывает `save_finding`, для завершения — `submit_report`. Находки сразу появляются в отчёте и остаются при отмене или ошибке модели; хранятся в памяти текущего сервиса, не переживают перезапуск процесса. Финальный отчёт объединяется с сохранёнными находками: отсутствие находки в последнем ответе не удаляет её. Планирование `write_todos` доступно, если harness предлагает его в текущем состоянии. Общие файловые инструменты, `task` и shell отфильтрованы из запроса и дополнительно блокируются при исполнении. Backend harness — виртуальное состояние, доступ к проекту реализован только через неизменяемый снимок в памяти. Исходники не подключаются как AGENTS.md, skills или инструкции.

По умолчанию включён управляемый обход: перед каждым основным запросом сервис передаёт очередной непрочитанный фрагмент (до 150 строк / примерно 6500 символов). Чтение через инструменты также продвигает очередь. До окончания очереди ранний submit_report отклоняется; при исчерпании бюджета разрешён частичный отчёт. Модель дополнительно выбирает связанные файлы для исследования. Полностью переданный модели файл не равен полностью проверенному. Непрочитанные и частично прочитанные файлы отображаются отдельно; неполный охват даёт статус `partial`. Бюджет времени и шагов может закончиться раньше очереди.

**Graphify 0.9.55** строит локальный AST-граф по тому же снимку исходников. Используется настоящий пакет `graphifyy`, его `graphify.extract.extract`, без LLM-обогащения, внешних API и установки skills. Разбор идёт в отдельном процессе с `python -I`, без импорта загруженного проекта; сетевые операции и запуск дочерних процессов блокируются Python audit hook. На индексацию отводится до 60 секунд отдельно от бюджета агента, результат ограничен 32 МиБ. При ошибке графа анализ исходников продолжается с явно указанной ошибкой.

Агент получает `graph_symbols(query)`, `graph_neighbors(symbol_id, direction)` и `graph_path(source_id, target_id)`. Ответы содержат идентификаторы, файлы/строки и происхождение связей. Узлы вне снимка и неоднозначные повторяющиеся идентификаторы исключаются. Соседи и поиск ограничены 20 результатами / 6000 символами, путь — 6 переходами / 2000 посещёнными узлами. Это граф структурных связей, не анализ потоков данных. Индексация не увеличивает охват чтения и не разрешает цитировать непрочитанный код. Файлы без узлов остаются в очереди анализа, их список есть в `report.graph.files_without_nodes`.

Для сравнения доступны `server.py --no-graphify` (тот же обход без графа) и `--no-managed-traversal` (модель сама выбирает все чтения). Вызовы `scan_agent` из Python включают функции явно через `graphify=True, managed_traversal=True`; веб-сервис включает их по умолчанию.

Находки содержат цитаты из прочитанных строк, CWE и условия эксплуатации. Агент указывает файл и диапазон ранее прочитанных строк; сервис сам подставляет точную цитату из снимка исходников. `verification: source_cited` означает только проверку соответствия цитат, а не доказанную эксплуатацию. Ссылки на непрочитанные или несуществующие строки отклоняются, модель может исправить отчёт в пределах бюджета. Если после отклонения доказательств модель убирает находку, она отмечается как незавершённая проверка, а не бесследно исчезает. Завершение обычным текстом без `submit_report` считается незавершённой проверкой. Сервис при этом собирает частичный отчёт из сохранённых находок (`report_source: service`), а не оставляет результат пустым без объяснения.

Лимиты по умолчанию: 30 основных шагов модели, 80 вызовов инструментов. Параметр `server.py --agent-steps 100` задаёт 100 шагов (допустимо 1–500); лимит инструментов равен максимуму из 80 и удвоенного числа шагов. Фактический лимит шагов отображается в интерфейсе и JSON-отчёте. Лимит времени Deep Agents — 30 минут (--agent-seconds 1800, проверяется между операциями); один запрос модели может длиться до 360 секунд. Ответ модели, включая сжатие истории, ограничен 8192 токенами (--max-output-tokens; допустимо 256–16384). Для этой конфигурации запускайте llama.cpp с контекстом не меньше 32768 токенов; прежний контекст 16384 не оставляет достаточно места для длинного ответа и входа. Каждый основной запрос модели получает свежие сведения о прочитанных диапазонах, следующих непрочитанных строках, сохранённых находках и бюджете; объём этих сведений ограничен. После 6 действий без новых прочитанных строк или изменений находок при пустой обязательной очереди агент переводится к завершению: доступны только сохранение находки и отправка отчёта. На этот этап отводится не больше 3 запросов; в последнем доступен только submit_report. Если отправка всё равно не удалась, сервис формирует частичный отчёт самостоятельно. Последние 3 шага также резервируются для завершения. Принудительное завершение помечается ошибкой/ограничением, даже при полном охвате чтения. Чтение — до 150 строк / примерно 6500 символов за раз; при указании только `start_line` конец диапазона рассчитывается автоматически; поиск — до 30 совпадений. Управление контекстом выполняет harness с профилем 12000 входных токенов под серверное окно 32768; это приблизительный бюджет, превышение окна отражается как ошибка. Внутреннее сжатие контекста может потребовать дополнительных запросов к той же локальной модели. Облачный LangSmith tracing отключён для запуска агента, HTTP-прокси отключены. API-совместимость инструментов не считается доказательством качества модели: проверяется отдельно на примерах.

**Последовательно**: прежний проход по фрагментам отдельных файлов для сравнения. Межфайлового исследования в этом режиме нет.

## ZIP и обработка

- ZIP до 25 МиБ, распакованный проект до 32 МиБ, не более 5000 записей.
- Структура сохраняется: `project/src/api.py` остаётся таким же путём в отчёте.
- Запрещены выход за каталог, абсолютные пути, символические ссылки, специальные файлы, дубли путей и зашифрованные архивы. Повреждённая распаковка удаляется.
- Поддерживаются распространённые языки: Python, JS/TS, Java/Kotlin, Go, Rust, C/C++, C#, PHP, Ruby, Swift, SQL, shell, HTML, Vue/Svelte и конфигурации JSON/YAML/TOML/XML/Terraform/Dockerfile.
- Пропускаются зависимости, сборки, `.git`, `.env*`, lock-файлы, бинарные/не-UTF-8 файлы, файлы больше 192 КиБ и строки длиннее 6000 символов. Каталоги исключаются целиком. `.gitignore` не интерпретируется.
- За проверку анализируются до 500 файлов и 8 МиБ текста. Все пропуски с причинами видны в отчёте.
- В последовательном режиме текст делится на фрагменты до 12000 символов с перекрытием до 15 строк. Запросы последовательные, таймаут ответа — 180 секунд. Остановка проверяется между запросами, текущий запрос может дождаться таймаута.

## Границы анализа и хранение

Это помощник для ревью, а не доказательство безопасности: возможны ложные находки и пропуски. Структура ZIP сохраняется целиком. Агент может исследовать связанные файлы, но формального анализа потоков данных, запуска приложения и проверки зависимостей по базе CVE нет. Инструкции внутри исходников считаются недоверенными данными; полностью исключить влияние prompt injection на вывод модели нельзя.

Некорректный/обрезанный JSON и ошибки сервера модели отображаются как ошибки анализа. Статус `partial` означает ошибку, незавершённое исследование или неполный охват; даже при `done` нужно учитывать список пропусков.

Оба сервера слушают localhost. Проверяемый код не исполняется. HTTP-прокси окружения отключены для запросов модели. Сервис рассчитан на одного локального пользователя: одна активная проверка, последний отчёт в памяти. ZIP распаковывается во временный каталог; предыдущий проект удаляется при следующей успешной загрузке, временные данные удаляются при нормальном завершении процесса. После аварийного завершения временная папка может остаться. Отчёт сохраняется на диск только при скачивании JSON пользователем.

## API

1. `GET /api/config` — получить `token` для заголовка `X-CSRF-Token`.
2. `GET /api/models` — доступные модели.
3. `POST /api/upload` — ZIP как тело запроса, `Content-Type: application/zip`; ответ содержит `project_id`.
4. `POST /api/scan` — JSON `{"project_id":"…","model":"…","mode":"deep"}`; `mode` может быть `deep` или `files`.
5. `GET /api/scan` — текущий/последний отчёт (до первого запуска `null`).
6. `POST /api/cancel` — JSON `{}`; остановка после текущего запроса модели.

Все POST требуют токен. Запросы с чужими Host/Origin отклоняются. Не публикуйте этот локальный интерфейс через reverse proxy без отдельной аутентификации и ограничений доступа.

## Проверки

Результаты запуска настоящей модели и обнаруженные ограничения: [VALIDATION.md](VALIDATION.md). На двух учебных примерах Qwen2.5-Coder прошла 0/2 строгих проверок, VulnLLM-R — 1/2, Qwen3.6 Unsloth — 2/2. Последняя привела доказательства межфайловой SQL-инъекции и не выдала находок на безопасном варианте. Эти результаты не заменяют оценку на независимых проектах.

```sh
.venv/bin/python -m unittest discover -s tests -v
```

Проверяются безопасная распаковка и лимиты, отбор файлов, нумерация фрагментов, валидация ответов, HTTP-защита, отмена и полный сценарий ZIP → llama.cpp-совместимый тестовый HTTP-сервер → отчёт. Тестовый сервер возвращает фиксированную находку и не проверяет качество реальной модели.


Для проверки настоящей модели запустите оба сервера и выполните:

```sh
.venv/bin/python -m scripts.evaluate
```

Скрипт загружает ZIP с двумя связанными файлами: HTTP-обработчиком и SQL-репозиторием. Уязвимый вариант конкатенирует ввод в SQL; безопасный использует параметры. Проверка требует чтения обоих файлов, SQL injection с доказательствами из двух файлов для уязвимого случая и отсутствия находок для безопасного. Отчёт записывается в `reports/live-evaluation.json` (предыдущий файл перезаписывается). Код фикстур не исполняется. Это проверка двух учебных примеров, а не оценка качества на произвольных проектах.


Проверки на исходниках OWASP NodeGoat и BenchmarkPython: [BENCHMARKS.md](BENCHMARKS.md). Для них доступен `evaluate_project.py`, принимающий готовый ZIP и сохраняющий журнал. После добавления серверного прогресса, сохранения находок и автоматического завершения оба новых прогона дали частичные отчёты: NodeGoat — 9 находок, BenchmarkPython — 7. Охват остаётся неполным, в безопасном примере найдено ложное срабатывание; качество и ограничения разобраны в BENCHMARKS.md. Для запуска со 100 шагами используйте `.venv/bin/python server.py --agent-steps 100` (по умолчанию остаётся 30).

Последнее сравнение Graphify и управляемого обхода без графа завершилось частичными отчётами во всех четырёх прогонах. Qwen не вызвала инструменты графа; улучшение точности не подтверждено. Таблица и ручная проверка находок: [BENCHMARKS.md](BENCHMARKS.md).

Для полностью прочитанного сохранённого прогона, где модель не отправила итоговый отчёт, доступно отдельное завершение:

```sh
.venv/bin/python -m scripts.finalize_report --report reports/nodegoat-qwen36-8k.json --output reports/new-final.json
```

ZIP должен совпадать по SHA256; все цитаты перепроверяются. Модель может сформировать только описание и ограничения, набор находок сохраняется без изменений. Старые ошибки формирования сохраняются для аудита; ограничения самого исследования остаются. Последний результат: [отчёт NodeGoat](../reports/nodegoat-qwen36-8k-final.md).
